# 青柠蛇场 V1 迭代计划

## 迭代目标

交付一个可在当前 Workspace 本地运行和测试、可通过 Git 迁移、可在后续独立正式环境中部署的贪吃蛇 V1。

## 交付物

### 产品

- 产品愿景、目标用户、范围和路线图。
- 核心玩法需求与可验证验收标准。
- V1 范围、优先级和交付边界。

### 设计

- 游戏主流程和异常恢复流程。
- 页面布局、视觉 Token、组件状态和响应式规则。
- 键盘、触屏、无障碍与微文案规范。

### 技术

- 前端系统架构和核心游戏状态模型。
- Canvas 渲染、输入控制、本地存储实现。
- 无后端依赖说明和关键技术决策。

### 测试

- 核心规则自动化测试。
- 桌面、移动、键盘和触屏测试用例。
- V1 验收记录，记录真实结果与遗留风险。

### 运维

- 本地环境和启动说明。
- 静态站点部署、生产配置和回滚指南。
- V1 发布说明，明确当前仅完成研发与测试环境交付。

## 优先级

### P0：V1 必须完成

- 游戏开始、移动、吃果实、增长、计分、加速。
- 墙体和自身碰撞判断。
- 轻松、经典、极速三种模式。
- 暂停、恢复、重新开始、游戏结束。
- 键盘与触屏操作。
- 本地最高分。
- 核心规则测试和浏览器主流程验收。
- Workspace 全空间交付文档。

### P1：允许随 V1 完善

- 浏览器切换到后台时自动暂停。
- 320 px 窄屏与横屏体验优化。
- 更清晰的状态播报与焦点管理。
- 生产部署前的性能预算和资源缓存策略。

### P2：后续版本候选

- 音效与静音控制。
- 每日挑战、障碍地图和历史记录。
- 高对比主题。
- 服务端排行榜或账号能力。

## 工作顺序

1. 产品空间确认范围和验收标准。
2. 设计空间定义主流程、页面规格和交互状态。
3. 技术空间确认架构、数据模型与实现约束。
4. 实现核心规则、界面与本地持久化。
5. 测试空间执行规则测试、浏览器验收并记录结果。
6. 运维空间准备独立生产环境的部署与回滚说明。
7. 代码和文档进入 Git；正式环境部署另行执行。

## 完成定义

V1 只有同时满足以下条件才视为可交付：

- P0 功能全部实现。
- 产品、设计、技术、测试与运维文档均有明确事实来源。
- 核心规则自动化测试通过。
- 目标浏览器主流程完成真实验收。
- 已知限制被记录，不用口头或聊天记录代替。
- Git 提交可以被其他环境拉取并按文档运行。
- 当前会话不直接操作正式环境。

## 变更控制

- 新增玩法先进入需求文档并确定优先级，不直接加入代码。
- V1 范围变化同步更新本计划和验收标准。
- 影响架构或长期维护成本的决定进入技术决策文档。
- 测试失败必须写入验收记录，不以聊天消息代替。
