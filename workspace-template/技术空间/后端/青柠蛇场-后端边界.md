# 青柠蛇场后端边界

## 当前结论

青柠蛇场 V1 不包含业务后端。游戏规则、渲染、输入和最高分全部在浏览器本地完成，正式环境只需托管静态文件。

## V1 不包含

- 用户注册、登录和身份鉴权。
- 数据库、对象存储或远程缓存。
- 云端最高分、排行榜或跨设备同步。
- 埋点收集、广告 SDK 和用户画像。
- WebSocket、多人对战和房间服务。

## 本地数据

| 数据 | 存储位置 | 生命周期 | 隐私说明 |
| --- | --- | --- | --- |
| 各模式最高分 | 浏览器 `localStorage` | 当前浏览器数据被清理前 | 不离开用户设备 |
| 当前游戏状态 | 页面内存 | 页面关闭或重开前 | 不持久化 |
| Workspace 文档 | Git + Workspace | 随项目长期维护 | 不包含个人凭据 |

## 引入后端的触发条件

只有出现以下已批准需求时才评估后端：

- 跨设备账号与进度同步。
- 公共排行榜或好友排行。
- 多人实时对战。
- 服务端活动配置与每日挑战。
- 必须集中管理的运营数据。

## 引入前必须补充

- 产品空间：用户价值、范围、验收标准与数据需求。
- 设计空间：登录、权限、加载、离线、错误与恢复流程。
- 技术空间：API、数据模型、安全、限流、反作弊与可观测性。
- 测试空间：接口、并发、安全、兼容和回归策略。
- 运维空间：环境、密钥、部署、监控、备份与回滚。
- 技术决策：服务形态、数据库和隐私边界的 ADR。

## 安全约束

- 不在 Workspace、源码或 Markdown 快照中保存 Token、密码和 Credential。
- 如未来接入远程服务，密钥只能通过正式环境的安全配置注入。
- 未经新的需求与设计评审，不增加任何远程数据上传。
