# 青柠蛇场源码索引与同步约定

## 目的

技术空间承担长期有效的技术事实、架构说明和源码阅读入口。可执行源码仍保存在仓库的工程目录中；为便于 Human 和不同 Agent 在 Workspace 内理解实现，关键源文件会同步为 Markdown 完整快照。

## 事实来源层级

1. **可执行源码**：实现行为的唯一事实来源。
2. **技术空间架构与决策**：解释为什么这样实现、边界是什么。
3. **源码 Markdown 快照**：便于阅读与检索，不作为独立实现分支。
4. **Git 历史**：保存每次变更的增量证据与责任边界。
5. **测试空间**：保存验证策略、用例和真实执行结果。

聊天记录、Agent 私有记忆和临时提示词都不能替代以上来源。

## 同步流程

修改源码时按以下顺序执行：

1. 修改 `snake-game/` 下的可执行源文件。
2. 根据变更更新技术架构、ADR 或产品需求；没有长期影响时不额外创建文档。
3. 运行 `npm run sync:code-backups` 生成 Markdown 快照。
4. 检查 Git Diff，确认源码与快照属于同一组变更。
5. 按测试空间定义执行验证并更新验收记录。
6. 用能让下一位 Agent 独立理解的 Commit 信息提交。

## 防漂移规则

- 不直接编辑 `技术空间/前端/源码备份/` 中的代码块。
- 不把 Markdown 快照复制回源文件；应修改源文件后重新生成。
- 源码和对应快照在同一 Git Commit 中提交。
- 仅修改注释、空白或临时调试时，也必须重新生成受影响快照。
- 如果快照与源码不一致，以可执行源码为准，并立即重新生成快照。

## Agent 上下文加载建议

- 理解业务目标：先读 `产品空间/需求文档/青柠蛇场-核心玩法需求.md`。
- 理解整体实现：读 `技术空间/技术架构/青柠蛇场-系统架构.md`。
- 定位代码：读本索引，再按任务加载单个源码快照或真实源文件。
- 调查取舍：读 `技术空间/技术决策/ADR-001-使用Canvas与原生Web技术.md`。
- 判断是否可交付：读测试空间的计划、用例和验收记录。
