# 本地文档与页面实时同步

## 交付要求

- 每次修改需求、架构、设计、交互、源码备份或其他长期项目内容，都必须保存至对应空间的本地文档。内容事实来源是本项目 `workspace-template/` 中的文件。
- 用户正在阅读的 Workspace 文档应自动显示本地文件的新内容，无需用户清空缓存、重新初始化、手工粘贴、切换浏览器或等待 GitHub 推送。
- 在页面保存文档时，必须先确认本地文件写入成功，再显示保存成功。服务不可用时须明确显示缓存或未同步状态，禁止仅保存至浏览器却声称本地文件已更新。
- 本地开发服务正常且没有冲突时，已打开的阅读页应在几秒内反映文件变化。当前实现每 1.5 秒检查一次；同内容不重新渲染，以保留滚动和交互状态。
- 动态设计成果仍在设计空间 Markdown 阅读页内展示，遵循设计空间交互规范。

## 版本保护

- 首次从旧浏览器缓存切换至工程文件前，备份旧副本，并提供恢复数据的导出入口。
- 用户正在编辑的未保存内容不得被文件轮询、热更新或 Agent 修改静默覆盖。
- 保存时比较本地文件与编辑开始时的版本；若不同，拒绝覆盖并提示合并。冲突解决之前不得宣称同步完成。
- 本地写入继续由 RoleAccessService / Workspace Guard 判断权限。同步不授予新的角色或专业空间权限。

## Agent 完成检查

1. 确认本地目标文件已保存。
2. 确认用户正在使用的 Workspace 文档路由读取到相同内容，不能用另一��新浏览器的初始化结果代替。
3. 对设计交互变更，确认该文档中的节点、详情与动态状态均来自当前文件。
4. 如果无法访问用户当前窗口，明确说明已验证的范围与仍需重新连接的窗口，不把推测写成已完成。

## 与 Git 的关系

本地文件与页面同步是每次交付的必要条件；Git 负责历史记录。是否推送 GitHub 由用户授权或已约定协作流程决定，本规范不增加自动推送要求。
